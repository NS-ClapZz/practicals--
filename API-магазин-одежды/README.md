# Практическая работа №3 по ИСРПО 12–13: API магазина одежды

Я реализовал REST API магазина одежды на ASP.NET Core 8, Entity Framework Core и SQLite.

## Что я реализовал

- Открытый каталог одежды и поиск по части названия без учёта регистра.
- Регистрацию и вход покупателей с хешированием паролей.
- Ролевую авторизацию покупателей и менеджера на основе cookie-сессии.
- Создание заказов с проверкой размеров и остатков, списание товара и сохранение цены, названия и размера на момент покупки.
- Просмотр заказов покупателя и фильтрацию по статусу.
- Менеджерские операции: изменение статуса заказа, остатка размера и доступности товара.
- Проверку статусов заказа: `New`, `Processing`, `Completed` и `Cancelled`.

## Запуск

Установи .NET 8 SDK или новее. Из папки `API-магазин-одежды` задай пароль менеджера и запусти API:

```powershell
$env:CLOTHES_MANAGER_PASSWORD = "задай-свой-пароль"
dotnet run --project .\ClothesApi\ClothesApi.csproj -- --urls http://localhost:5000
```

Логин менеджера задаётся переменной `CLOTHES_MANAGER_LOGIN`; если её не задать, используется `manager`. Пароль сохраняется в базе только в виде хеша. При первом запуске я создаю SQLite-базу `clothes.db` и демонстрационный каталог.

## Проверка через Postman

Я подготовил коллекцию из 13 запросов и окружение Postman. Импортируй оба файла, укажи `baseUrl` и задай локальное значение `managerPassword`, совпадающее с `CLOTHES_MANAGER_PASSWORD` запущенного API. Не экспортируй пароль в файл окружения.

24 октября 2026 года я повторно проверил API: сборка решения прошла без предупреждений и ошибок, а запуск коллекции через Newman выполнил все 13 запросов и прошёл все 22 автоматические проверки. В приложенных снимках показан сохранённый прогон Postman от 20 октября; сами снимки я обновил 24 октября. Новый результат проверки через Newman приведён здесь отдельно, поэтому снимки не выдаются за новый запуск в интерфейсе Postman.

В API реализованы публичные маршруты `GET /api/health` и `GET /api/clothing`, регистрация и вход по маршрутам `/api/users/register` и `/api/auth/login`, работа с заказами, а также менеджерские маршруты `/api/manager/...`.
